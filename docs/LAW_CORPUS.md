# Law Corpus Documentation

> **Status:** Complete
> **Location:** `law_corpus/`

Fuzzzy Law's intelligence relies heavily on a highly curated, accurate, and properly chunked corpus of Georgian law.

## Included Legal Sources

The corpus consists of **20,712** chunks distributed across 3 ChromaDB collections:

1. **`georgian_laws` (15,338 chunks)**
   Contains the 12 primary legal codes of Georgia, scraped from matsne.gov.ge.
2. **`court_practice` (5,197 chunks)**
   Contains Supreme Court rulings (2022–2026), providing practical interpretations of the law.
3. **`grand_chamber` (177 chunks)**
   Contains binding decisions from the Grand Chamber of the Supreme Court, which override lower court interpretations.

## Data Processing Pipeline

### 1. Scraping (matsne.gov.ge)
The legal codes are scraped from the official Georgian legislative herald (matsne.gov.ge). The pipeline parses complex HTML structures to ensure we extract the exact, consolidated, and up-to-date versions of the texts, bypassing legacy or unconsolidated versions.

### 2. Chunking
Chunks are created semantically, usually at the article or paragraph level. This ensures that a chunk contains a complete, actionable piece of law without cutting off critical context.
- **Laws Metadata:** `code_name`, `article_number`, `article_title`, `citation_text`, `source_url`, `article_url`, `document_number`
- **Court Practice Metadata:** `case_id`, `category` (criminal/civil/administrative), `year`, `section`, `chunk_index`
- **Grand Chamber Metadata:** `case_id`, `category`, `year`, `norm_interpreted`, `binding_rule`, `section`

### 3. Embeddings
All text chunks are embedded using Google's Vertex AI `gemini-embedding-001` model (768 dimensions). 
**CRITICAL:** The corpus is embedded using `task_type=RETRIEVAL_DOCUMENT`. All incoming user queries must be embedded using `task_type=RETRIEVAL_QUERY` to ensure accurate vector distance calculations.

## Extending the Corpus

### How to Add a New Legal Source
1. Determine the source category (is it a new code, a regulation, or court practice?).
2. Write a scraper that produces raw JSON matching the existing schema.
3. Apply the standard semantic chunking logic.
4. If it's a new type of source, you may need to define a new ChromaDB collection and update `RAGCollectionConfig` in the backend.

### How to Re-embed the Corpus
If you need to switch embedding models or correct data integrity:
1. Purge the specific collection using ChromaDB's client API.
2. Re-run the embedding pipeline script.
3. Verify the counts using `GET /api/v1/health/ready` or a local python script.

## Data Quality Guarantees

We enforce strict data fidelity checks to ensure the AI does not hallucinate fake laws.
- The Eval Pipeline uses a strict holdout mechanism to test the AI on 50 real Supreme Court cases. The AI's `article_accuracy` score measures whether it cited the correct laws for a given case.
- Citations generated by the AI are regex-parsed and cross-referenced with the corpus metadata (`article_number`, `code_name`).
