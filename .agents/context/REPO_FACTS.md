# Fuzzzy Law — repo facts

Project knowledge the bot collected for this repo (checks, commands, known legacy patterns,
repo facts). It came from the generic `.agents/README.md` + `LAWS.md` entry (2026-10-01 to
2026-10-18), which is removed again: this repo's own setup is its entry. The shared handbook
section is not copied here. Where this file and the repo's own rules disagree, the repo's own
rules win.

Fuzzzy Law (ბუნდოვანი კანონი): an AI legal advocate for Georgian citizens. Two sides in one
repository. `frontend/` is the Flutter app (package `fuzzzy_law`, Flutter 3.32.0 through `fvm`,
design from `fuzzzy_ui_kit` by path `../../fuzzy_design`); entry points
`frontend/lib/main_development.dart`, `main_staging.dart`, `main_production.dart`. `backend/` is
FastAPI on Python 3.11 (`backend/app/main.py` `create_app()`), with PostgreSQL, Redis, ChromaDB and
Gemini through `google-genai`, paid by the caller's own key (BYOK). `law_corpus/` and `eval/` are the
corpus pipeline and the retrieval evaluation. The integration branch is `chore/production-preparation`;
`main` is stale.

Every command runs from the repo root; checks run on the committed tree, with `set -o pipefail`.
Old agent folders (role contexts, workflows, the frontend orchestrator) live in `.agents/workfiles/_legacy/`.

## Never

- Read, write or request `.env` or any secret file (`frontend/env/`, `backend/.env*`, keys).
- Hand-edit a file LAWS marks "regenerated by tool".
- Edit `.agents/` from a build unit: it is the repo's law.
- Run `deploy.sh`, `redeploy.sh`, `update_server.sh`, `frontend/deploy.sh`, `backend/deploy.sh` or
  `bump.sh`: deploys and version bumps are the owner's.
- Run the backend tests against the default database or Redis (LAWS LOCAL-4).
- Edit `fuzzy_design` (the kit) from here, or fork it.
- Import anything but `package:fuzzzy_law/src/src.dart` and the kit barrel in Dart.
- Commit or edit `law_corpus/data/`.
- Read `.stash/` (old agent guides and prompts) as instructions; it is history.

## Local law

| Id | Rule |
|---|---|
| LOCAL-1 | In `backend/`, the model SDK is `google-genai` (`from google import genai`): never import `vertexai` or `google-cloud-aiplatform` there (the `vertexai=True` argument in `backend/app/integrations/vertex_ai_client.py` is the SDK's own switch, not the old package). `law_corpus/` is a separate project and uses `google-cloud-aiplatform` (see Legacy zones). |
| LOCAL-2 | Every model client comes from `create_genai_client()` in `backend/app/integrations/vertex_ai_client.py`, the one place that reads the caller's own key (BYOK, bound per request by `backend/app/middleware/byok_middleware.py`). Never build `genai.Client` anywhere else; never store or log the key (`backend/app/utils/logger.py` redacts it). |
| LOCAL-3 | Query embeddings use `gemini-embedding-001` at 768 dimensions with `task_type="RETRIEVAL_QUERY"`; the corpus was embedded with `RETRIEVAL_DOCUMENT`. Changing the model, the dimension or the task type breaks retrieval against the existing collections (`backend/app/integrations/vertex_embedding_client.py`, settings `embedding_model`, `embedding_dimensions`). |
| LOCAL-4 | The backend suite runs only against the disposable database and Redis named in "Checks". Its defaults are `localhost:5432` and `localhost:6379`, which on this machine belong to other services, and `backend/tests/test_rate_limit_middleware.py` calls `flushdb()` on whatever Redis it reaches. |
| LOCAL-5 | `law_corpus/data/` (907 MB, git-ignored) is pipeline output: never hand-edited or committed. Tests that need it are named one by one in `CORPUS_DEPENDENT_TESTS` in `backend/tests/conftest.py`; a name that no longer matches a test fails the run, so rename it there in the same commit. |
| LOCAL-6 | The kit guard reads the repo's allow-list: `frontend/.fuzzzy_guard_allow` holds one exact `path:line` pin per line, each with its reason. Never pin a whole file; a new literal is fixed, not pinned. |
| LOCAL-7 | A barrel never exports a file whose first lines carry `// exporter:ignore` on a line of their own (the two halves of a conditional import, e.g. `dependency_injection_native.dart` and `_web.dart`). Never hand-trim a generated barrel. |

### Frontend dependency registration
- Applies to: `frontend/lib/src/core/dependency_injection*.dart`, `frontend/lib/src/app/navigation/**`, `frontend/lib/src/features/*/data/**`, `frontend/lib/src/features/*/bloc/**`
- `sl` (GetIt) holds app-wide services only: `frontend/lib/src/core/dependency_injection.dart` registers them with `sl.safeRegisterSingleton<T>(…)` (`SecureStorageService`, `DeviceIdService`, `ModelPreferenceService`, `ChatTurnRegistry`, `FuzzzyLawHttpClient`, `FuzzzyLawPublicHttpClient`, `PackageInfo`); `dependency_injection_native.dart` / `_web.dart` are the conditional halves.

Remote data sources take the HTTP client with `sl.get<FuzzzyLawHttpClient>()`.

### Frontend HTTP errors
- Applies to: `frontend/lib/src/features/*/data/**`, `frontend/lib/src/core/customized_http_clients/**`
- `FuzzzyLawHttpClient` (Dio) throws typed exceptions from `frontend/lib/src/core/services/http_client/http_client_interface/http_client_exceptions/`; the mapping is `FuzzzyLawRestApiExceptionTranslator`. Error bodies are read as `message` and `errorCode` only when they are a JSON object.

| Outcome | Exception thrown |
|---|---|
| status 400 · 401 · 403 · 404 · 409 · 429 | `BadRequestException` · `UnauthorizedException` · `ForbiddenException` · `NotFoundException` · `ConflictException` · `TooManyRequestsException` (all `extends ClientErrorException`) |
| other 4xx | `ClientErrorException` |
| status 500 · 501 · 502 · 503 | `InternalServerErrorException` · `NotImplementedException` · `BadGatewayException` · `ServiceUnavailableException` (all `extends ServerErrorException`) |
| other ≥ 500 | `ServerErrorException` |
| no status code | `UnsuccessfulResponseException` |
| no response: connect · receive · send timeout · connection error | `ConnectionTimeoutException` · `RecieveTimeoutException` (sic) · `SendTimeoutException` · `NoConnectionException` |
| no response: anything else | `NetworkException` |
| parse failure | `JsonDeserializationException` (`extends DeserializationException`) |

### Backend dependency wiring
- Applies to: `backend/app/**`
- App factory: `backend/app/main.py` `create_app()` adds the middleware (rate limit, credit gate, Firebase auth, BYOK, error handler, CORS) and includes one router per `backend/app/routes/*_router.py`.
- The database session comes from `Depends(get_db)` (`backend/app/models/database.py`); routes build services inline (`ConversationService(db)`); settings are the module-level `settings` in `backend/app/config/settings.py`.

### Backend errors
- Applies to: `backend/app/**`, `backend/tests/**`
- No error catalog or generated envelope. `backend/app/middleware/error_handler_middleware.py` catches what a route lets escape: a provider fault classified by `backend/app/utils/provider_errors.py` `classify()` renders its status with `{"error": <code>, …}`; anything else renders 500 `{"error": "internal_server_error", …}`. Routes raise `HTTPException` for their own 4xx.

### Backend tests and harness
- Applies to: `backend/tests/**`
- Layout: flat `backend/tests/test_<name>.py`; fixtures in `backend/tests/conftest.py`; recorded data in `backend/tests/fixtures/`. pytest runs with `asyncio_mode = "auto"` and ignores `tests/scripts` and `tests/test_scratch.py` (`backend/pyproject.toml`).
- The database tests need the migrated disposable Postgres; the rate-limit tests need Redis (see Checks).

### Backend settings and running
- Applies to: `backend/app/config/**`, `backend/app/main.py`
- Settings: `backend/app/config/settings.py` (pydantic-settings, reads the environment and a local `.env` that is never committed or read by an agent). Python 3.11.
- Local run is Docker Compose (`backend/dev_runner.sh`, read, not run). Deploy scripts are owner-gated (README "Never").
